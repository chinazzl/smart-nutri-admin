## T1: 搭建饮食模块架子

**目标**：创建饮食日记的基础页面结构和路由

### 步骤
1. 创建 `src/views/nutrition/index.vue` 页面骨架（空壳，仅有 `<template>` 和基础 div）
2. 创建 `src/router/nutrition.ts` 路由配置，路径 `/nutrition`，需登录权限
3. 在 `src/router/index.ts` 中导入并注册 nutrition 路由
4. 在 `src/components/Sidebar.vue` 中添加菜单项「饮食日记」
5. 创建 `src/api/nutrition.ts`，封装以下请求方法（Mock 数据，暂不连后端）：
   - `getNutritionLogs(date: string)`
   - `addNutritionLog(data)`
   - `updateNutritionLog(id, data)`
   - `deleteNutritionLog(id)`
   - `searchFoods(keyword: string)`
   - `getDailyGoals()`
   - `updateDailyGoals(goals)`

### 验收
- [ ] 访问 `/nutrition` 能看到页面（即使是空壳）
- [ ] Sidebar 菜单有「饮食日记」入口

## T2: 食物数据层

**目标**：建立食物库数据类型和搜索能力

### 步骤
1. 创建 `src/types/nutrition.ts`，定义以下接口：
   - `Food` — 食物基本信息
   - `NutritionLog` — 单条饮食记录
   - `DailyGoal` — 每日营养目标
2. 创建 `src/data/foods.json`，内置 50+ 常见食物数据（格式：`{ id, name, calories, protein, carbs, fat, unit }`）
3. 创建 `src/utils/foodSearch.ts`，实现模糊搜索函数：
   - 输入关键词，返回匹配食物列表（按名称拼音首字母和汉字双重匹配）
   - 支持大小写不敏感

### 验收
- [ ] TypeScript 类型无报错
- [ ] 搜索"鸡"能返回鸡胸肉、鸡蛋等相关食物

## T3: 饮食记录页面 UI

**目标**：完成饮食日记主页面所有 UI 组件

### 步骤
1. **日期选择器**：使用 Element Plus `el-date-picker`，默认当天，支持切换历史日期
2. **今日摘要卡片**：4 列卡片，展示今日总热量、总蛋白质、总碳水、总脂肪（数据来自所有餐次汇总）
3. **营养目标环形图**：使用 ECharts 渲染 4 个环形图（热量/蛋白质/碳水/脂肪），显示已摄入百分比
4. **餐次分组列表**：
   - 早餐 / 午餐 / 晚餐 / 加餐 四个折叠面板
   - 每个面板显示该餐所有食物列表（名称 + 重量 + 热量）
   - 每个面板底部显示该餐小计
   - 每个面板右上角有 [+ 添加] 按钮
5. **空状态**：如果当日无任何记录，显示引导文案「还没有饮食记录，开始记录今日饮食吧」

### 验收
- [ ] 日期切换后数据正确更新
- [ ] 4 个环形图正确显示百分比
- [ ] 4 个餐次折叠面板正常展开/折叠

## T4: 添加食物功能

**目标**：用户点击 [+ 添加] 后弹出搜索框完成食物添加

### 步骤
1. 创建 `src/components/nutrition/FoodSearchDialog.vue` 弹窗组件
2. 弹窗 UI：
   - 顶部搜索输入框（`el-input`）
   - 搜索结果列表（`el-scrollbar`），每个结果显示：食物名称 + 每100g热量
   - 点击选中后，显示份量输入框（默认 100g）
   - 选中后实时预览该份量的营养素数值
   - 底部 [取消] [确认添加] 按钮
3. 在 `NutritionLog` 页面中引用该组件，传入当前 `date` 和 `meal_type`
4. 提交后调用 `addNutritionLog` API，成功后刷新当日列表并重新计算汇总

### 验收
- [ ] 点击 [+ 添加] 弹出搜索弹窗
- [ ] 输入关键词显示匹配食物
- [ ] 选择食物后输入份量，预览营养素
- [ ] 确认后记录出现在对应餐次中

## T5: 编辑/删除记录

**目标**：支持修改和删除已有的饮食记录

### 步骤
1. **编辑**：
   - 在食物列表中每条记录右侧添加 [✏️ 编辑] 按钮
   - 点击后弹出编辑弹窗（复用 T4 的 FoodSearchDialog，prefill 当前数据）
   - 修改份量后实时预览新营养素值
   - 确认后调用 `updateNutritionLog`，成功后刷新列表
2. **删除**：
   - 在食物列表中每条记录右侧添加 [🗑️ 删除] 按钮
   - 点击后弹出 `el-message-box` 确认对话框
   - 确认后调用 `deleteNutritionLog`，成功后刷新列表

### 验收
- [ ] 编辑后数据正确更新，汇总数据同步更新
- [ ] 删除前有二次确认
- [ ] 删除后记录消失，汇总数据同步减少

---

## T6: 每日目标设定

**目标**：用户可自定义每日营养素目标

### 步骤
1. 在页面右上角添加 [⚙️ 设置目标] 按钮
2. 点击后弹出 `el-dialog`，内含 4 个 `el-input-number`：
   - 每日热量目标（默认 2000 kcal）
   - 每日蛋白质目标（默认 60g）
   - 每日碳水目标（默认 250g）
   - 每日脂肪目标（默认 65g）
3. 保存后调用 `updateDailyGoals` API，保存到 Pinia store
4. 环形图实时根据新目标更新百分比

### 验收
- [ ] 可以打开目标设定弹窗
- [ ] 目标数据持久化（刷新页面后保留）
- [ ] 环形图百分比随目标变化而正确更新
- [ ] 超标时环形图显示红色（>100%）

## T7: 响应式与细节优化

**目标**：提升用户体验，补齐细节

### 步骤
1. **移动端适配**：使用 `el-row` / `el-col` 响应式布局，使仪表盘在手机上可读
2. **加载状态**：数据请求时显示 `el-skeleton` 骨架屏
3. **Toast 提示**：操作成功/失败后显示 `ElMessage` 提示
4. **边界处理**：
   - 份量不能为负数或 0
   - 搜索无结果时显示"未找到相关食物"
5. **数据校验**：目标设定弹窗中数值范围校验（热量 500-5000，宏量营养素 0-500）

### 验收
- [ ] 手机屏幕下布局正常
- [ ] 加载中显示骨架屏
- [ ] 操作后有 toast 反馈
- [ ] 无数据/异常状态有友好提示
