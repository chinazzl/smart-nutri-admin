## ADDED Requirements

### Requirement: 角色菜单与路由差异化展示
系统 SHALL 根据登录用户的角色（管理员 admin / 普通用户 user）过滤侧边栏菜单，并限制非法路由越权访问。
- 第一步：用户成功登录并跳转至系统后，`Sidebar` 导航菜单组件读取 `userStore` 中当前登录用户的 `role` 字段。
- 第二步：如果是 `admin` 角色，侧边栏菜单仅加载并渲染“仪表盘”、“用户管理”、“健康档案”三个项，对普通用户功能进行隐藏。
- 第三步：如果是 `user` 角色，侧边栏菜单加载并渲染“仪表盘”、“饮食日记”、“运动追踪”、“AI健康助手”、“健康档案”，隐藏“用户管理”。
- 第四步：全局路由守卫在每次路由跳转前，检查目标路由的 `meta.roles` 角色白名单。
- 第五步：若普通用户尝试在地址栏手动输入 `/user-management` 进行越权访问，路由守卫拦截该操作，将其重定向回 `/dashboard`。

#### Scenario: 普通用户手动输入管理员URL被拦截
- **WHEN** 登录角色为“user”的用户在浏览器地址栏手动输入并敲击回车访问 `/#/user-management`
- **THEN** 路由守卫必须拦截该路由，将其重定向至 `/#/dashboard`，并调用 Element Plus 提示用户“无权限访问该资源”

### Requirement: 管理员用户管理控制台
系统 SHALL 为管理员提供可视化的用户列表表格，并支持状态切换、角色变更与健康档案快照预览。
- 第一步：管理员点击进入“用户管理”页面，系统从本地存储（localStorage）或 mock API 加载当前系统所有已注册的用户数据列表。
- 第二步：列表使用表格渲染，列出用户基本信息（用户名、账号角色、注册时间、状态）及操作操作按钮。
- 第三步：管理员点击某一行用户右侧的“启用/禁用”开关或按钮，系统修改该用户的状态，写入本地持久化。
- 第四步：管理员选择角色切换下拉框，对用户的角色（admin/user）进行修改，写入持久化。
- 第五步：管理员点击“查看身体档案”按钮，系统在右侧拉出 Drawer 抽屉，展示该用户在 profile 中设置的身高、体重、BMI 等分析卡片。

#### Scenario: 管理员切换普通用户状态为禁用
- **WHEN** 管理员在用户“李四”所在的行点击“禁用”按钮并确认
- **THEN** 系统必须将“李四”的状态更新为 `disabled` 并写入本地缓存。此后，李四使用该账号登录时，系统必须阻止登录并提示“账号已被禁用”
